## [0.4.0] - 2026-11-24

### Added
- Engine command `reindex <file>` makes the agent's new Index the Index. It prints the Rule delta as JSON (`unchanged`, `moved`, `changed`, `added`, `removed`, `audit`), carries Verdicts and Baseline protection across for unchanged and renumbered Rules, and deletes the input file. Invalid input exits 1 and changes nothing.

### Changed
- Editing the Standard and running `eqc check <path>` re-indexes instead of resetting. Verdicts are kept, and only added and changed Rules are re-audited. Use `eqc reset` and then `eqc check <path>` for a full rebuild.
- A Re-index can lower the Baseline level when the Standard raises the bar. Later merges ratchet it up again.

### Fixed
- Re-index no longer attaches a stale Verdict to a newly added Rule. Only Rules in the old Index carry Verdicts across.
- The new Index is validated with `check-ids <doc> <index-file>` before install, so a mismatch leaves state untouched. The editing-Standard flow runs it on `.eqc/tmp/rules.next.json` before `reindex`.
- Re-index regenerates the report when only a Baseline existed, not only when `compliance.json` existed.

## [0.3.0] - 2026-11-18

### Added
- One State schema for all of `.eqc/`, recorded as `state_schema` in `.eqc/config.json` (missing means 1; current is 2). `init` writes it.
- Engine command `migrate` upgrades `.eqc/` state in place. It backs up every `.eqc/*.json` to `.eqc/tmp/backup-schema-<N>/` first and restores that backup if a Migration fails.
- Migration 1 → 2 builds the Baseline from recorded Verdicts when `baseline.json` is missing (projects started on 0.1).
- Schema gate: Engine commands other than `selftest` and `check-ids` refuse to run when `state_schema` does not match the Engine, telling you to run `npx eqc-kit update` (older) or upgrade eqc-kit (newer).
- `npx eqc-kit help` (also `--help`, `-h`, or no command) prints a quick start, every installer command with key flags, and the docs link. `npx eqc-kit help <command>` shows one command's purpose, flags and an example. Works before install; an unknown command exits 1.
- Agent help: `/eqc-help [question]` (Claude Code) and `eqc help [question]` (AGENTS.md agents) follow `.eqc/prompts/help.md`. They run `doctor`, report your Compliance level and next fix, and answer. Read-only: they name the command to run instead of running a writing one.
- Install writes `.eqc/prompts/help.md`, and with the `claude-code` adapter `.claude/skills/eqc-help/SKILL.md`. The `init` next-step output mentions help.

### Changed
- `npx eqc-kit update` runs `migrate` after syncing the Engine, and exits 1 with the Engine's error if the migration fails.

## [0.2.0] - 2026-11-17

### Added
- Write-time guardrail: the `AGENTS.md` block (and a `CLAUDE.md` block when `CLAUDE.md` exists, since Claude Code then ignores `AGENTS.md`) tells agents to follow `.eqc/RULES.md`, keep protected Rules passing, never weaken checks, and run `verify` and `guard` before finishing.
- Rule digest `.eqc/RULES.md`, regenerated by `merge` and `report --write`.
- Optional `verify` command per Rule in `rules.json` (written by the indexer for mechanically checkable Rules) and Engine `verify [ID,...]`, which runs it for passing Rules only.
- Compliance baseline (`.eqc/baseline.json`): each merge protects Rules that pass and keeps the highest level reached. `eqc guard [--min TIER]` exits 1 when a protected Rule regresses, the level drops, or the level is below `--min` (replaces the planned `report --check-tier`); `reset` removes the baseline.
- `.eqc/hooks/pre-commit` (`verify`) and `pre-push` (`verify` + `guard`), enabled per clone with `npx eqc-kit hooks` (`--off` to disable); never replaces another hook manager. CI example in docs/ci.md.
- Report sections: a `Baseline:` line, `## Regressions`, `## To reach <Tier>` (blocking Rules) and `## Not audited`.
- Code map: `/eqc-check` and `/eqc-fix` use an existing code map when it is fresh, skip a stale one with a refresh hint, and never build one.
- HTML report `COMPLIANCE.html` written next to the Markdown report on every `merge` and `report --write`: a single self-contained page (no JavaScript) with level and tier progress, what needs attention, and all Rules by tier.

### Changed
- `/eqc-check` prints the report verbatim and names Rules as `ID — title`; re-checks show `before → after`; after each merge it runs the guard and shows regressions.

## [0.1.0] - 2026-09-29

### Added
- `npx eqc-kit init | update | uninstall | doctor` — interactive or `--yes --config` setup, stack/CI/package-manager detection, managed files with hash manifest (edited files are never silently overwritten or removed).
- Zero-dependency Engine (`.eqc/bin/eqc.mjs`): doc-defined tiers, verdicts `pass | partial | fail | na`, compliance level maths (unaudited rules block a tier), ranked fix candidates, chunked plans, milestones, auto-regenerated report, `check-ids` index validation, `reset`.
- Harness-neutral Prompts: check, fix, index, audit, plan, fixer.
- Adapters: Claude Code (skills + subagents, optional cheaper model for mechanical chunks) and AGENTS.md (Codex, Cursor, Copilot, Gemini CLI, others).
- Example three-tier standard and full documentation.
