# eqc-kit

A tool-agnostic kit that helps any developer raise their project's compliance with a tiered engineering-quality standard. The kit provides an interactive installer, a vendored zero-dependency engine, and AI agent adapters.

## Language

### The standard

**Standard**:
The user-supplied document of ordered tiers of numbered rules, defining what constitutes "quality" for a project.
_Avoid_: spec, checklist, policy

**Tier**:
One ordered level of the Standard, named by the document (e.g., Bronze, Silver, Gold, or L1, L2, L3). Every project has a Compliance level equal to the highest Tier reached.
_Avoid_: level, grade

**Rule**:
One numbered item within a Tier. Each Rule has an ID formatted as `<TIERID>-<number printed in the doc>`, never renumbered.
_Avoid_: check, requirement, item

**Applicability tag**:
A stack label on a Rule (e.g., [web] [backend] [mobile]), used to filter which Rules apply to this project.
_Avoid_: platform tag, language tag

### Measuring

**Index**:
The machine-readable rules.json extracted from the Standard, containing all Rules, their IDs, Tiers, Applicability tags, and descriptions.
_Avoid_: parse, catalog

**Audit**:
The process of evaluating Rules against the codebase to determine pass/partial/fail Verdicts with evidence.
_Avoid_: scan, check

**Verdict**:
The audit result for one Rule: pass | partial | fail | na. pass (Rule fully satisfied), partial (partly satisfied), fail (not satisfied), na (Rule does not apply to this project; evidence says why, and it is not a fail). Evidence is recorded.
_Avoid_: score, grade

**Compliance level**:
The highest Tier reached. A Tier is reached when every Rule in it and in every lower Tier has a Verdict and none is a fail (partial and na do not block; unaudited Rules do). If the lowest Tier has a fail, Compliance level is HARD_FAIL (it takes precedence); if it has no fail but is not fully audited, the level is NONE.
_Avoid_: score, current tier

**Verify command**:
An optional shell command on a Rule in the Index that exits 0 when the Rule is met. Run by the Engine's `verify` for passing Rules only, from git hooks and CI. Only for Rules a command can check mechanically.
_Avoid_: check, lint rule, test

**Rule digest**:
`.eqc/RULES.md`, the compact list of Rules with their latest Verdicts that agents read before writing code. Regenerated by `merge`.
_Avoid_: summary, cheat sheet

**Baseline**:
The highest Compliance level the project has reached, plus every Rule that has passed, recorded by the Engine in `.eqc/baseline.json`. It only ever rises; a later fail never lowers it.
_Avoid_: snapshot, ratchet file

**Protected rule**:
A Rule recorded as pass in the Baseline. Any later Verdict other than pass or na for it is a Regression.
_Avoid_: locked rule, frozen rule

**Regression**:
A Protected rule whose current Verdict is fail or partial, or a Compliance level below the Baseline level.
_Avoid_: break, drop

**Guard**:
The Engine check (`eqc guard`) that compares current Verdicts with the Baseline and exits non-zero on any Regression. It reads recorded Verdicts only; re-auditing is the agent's job.
_Avoid_: gate (a Gate is an approval pause), lock
_Note_: `verify` checks the code itself; Guard checks recorded Verdicts. Git hooks and CI run both.

**Code map**:
A pre-built index of the project's code (symbols, calls, dependencies), such as a graphify graph, used to explore before reading files. Used only when fresh: not older than the latest commit or uncommitted changes.
_Avoid_: code graph, codemapper (when meaning the concept)

### Improving

**Effort tier**:
A sizing label for a fix: trivial, small, medium, or large, used to estimate work required.
_Avoid_: size, complexity

**Blast radius**:
Tags on a failing Verdict (e.g., ci-config, package-install, architecture, large-sweep) indicating the scope and risk of a fix, used to decide Gates.
_Avoid_: risk, impact

**Gate**:
An approval pause before applying a risky fix, triggered by Blast radius tags.
_Avoid_: guard, check

**Plan**:
A chunked, reviewable fix plan for one medium or large failing Rule, broken into resumable Chunks.
_Avoid_: proposal, roadmap

**Chunk**:
One resumable step of a Plan, mechanical or requiring judgment. Chunks are numbered, run in order, and a Plan can be resumed at the next unticked Chunk.
_Avoid_: step, batch

**Milestone**:
A log entry recording the outcome of a fix: done, partial, blocked, or failed.
_Avoid_: status, checkpoint

### Installation

**Engine**:
The deterministic zero-dependency script (`.eqc/bin/eqc.mjs`) that owns all state files and the tier maths. It never judges code against prose Rules — Audits are done by the agent following a Prompt. It only runs the Verify commands the Index defines.
_Avoid_: CLI, runner

**Installer**:
The `npx eqc-kit` command (subcommands: init, update, uninstall, doctor) that sets up the `.eqc/` directory and generates Adapters.
_Avoid_: setup, bootstrap

**Adapter**:
Generated files that wire Prompts into one AI tool (Claude Code .claude/skills + .claude/agents, or AGENTS.md for any agent). One per tool.
_Avoid_: plugin, integration

**Prompt**:
A harness-neutral markdown playbook in `.eqc/prompts/` that an agent follows to audit or fix Rules. Prompts never name a specific AI tool or hook.
_Avoid_: skill, command, script

**State schema**:
The single integer `state_schema` in `.eqc/config.json` naming the format of all `.eqc/` state files together. A missing field means 1. Only a Migration changes it.
_Avoid_: schema version, kit version (the kit version is `installed_version`)

**Migration**:
One ordered step that rewrites `.eqc/` state from State schema N to N+1 without losing Verdicts, Baseline, Milestones or config. Migrations run during `update`, never during an Audit.
_Avoid_: upgrade (the whole `update` run), conversion

**Managed file**:
A file or code block written by the Installer, carrying an eqc-kit marker comment, safe to regenerate on update or reinstall.
_Avoid_: generated file, template
